# SillyTavern Supabase + Vercel Fast-Path Migration Guide

This guide reflects the exact, fastest-path strategy to migrate SillyTavern to a Vercel-hosted architecture using Supabase. The scaffolding has been added to your codebase today.

## What Was Done Just Now
1. **Supabase Schema Creation**: Wrote `supabase-schema.sql` defining your `profiles`, `chats`, `characters`, and `embeddings` (`pgvector`) schema.
2. **Supabase Client Library Installation**: Ran `npm install @supabase/supabase-js dotenv`.
3. **Environment Setup**: Generated a `.env.example` file.
4. **Vercel Serverless Export**: Appended `export { app };` to `src/server-main.js` so it can be deployed via serverless HTTP functions.
5. **Vercel Lambda Handler**: Created `api/index.js` which points `/api` routes directly into the Express app while safely mapping `DATA_ROOT` to `/tmp` to avoid Vercel filesystem crashes on day one.
6. **Vercel Config**: Generated `vercel.json` to handle frontend static file routing and backend `/api/` routing.
7. **Abstract Storage Shim**: Created `src/supabase.js` as the interface we will use to intercept server `import/export/append` operations.

## Step 1: Set Up Supabase (10 Minutes)
1. Go to [Supabase](https://supabase.com) and create a new project.
2. Go to the **SQL Editor** on the left menu.
3. Open `supabase-schema.sql` (in your workspace root) and paste its **entire contents** into the editor and hit **Run**.
   *This activates PgVector, setups your tables for JSONL chats and Character PNGs, and prepares the Storage block.*
4. Go to **Project Settings -> API** and copy:
   - Your **Project URL**
   - Your **service_role secret** key (DO NOT share this publicly).

## Step 2: Configure Environment (2 Minutes)
1. Copy `.env.example` to `.env`.
2. Paste your `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` in the newly created `.env` file.

## Step 3: Test and Deploy to Vercel (10 Minutes)
1. Commit the changes generated by this session to your fork on GitHub.
   ```bash
   git add .
   git commit -m "feat: Add Vercel and Supabase Serverless Foundation"
   git push
   ```
2. Go to [Vercel](https://vercel.com/) and click **Add New Project**.
3. Import your SillyTavern GitHub repository.
4. Expand **Environment Variables**:
   - Add `SUPABASE_URL` and paste your URL.
   - Add `SUPABASE_SERVICE_ROLE_KEY` and paste the secret role key.
   - Add `VERCEL_MODE` with value `true`.
5. Click **Deploy**.

## Day One Architecture Note (Why This Was Fast)
To get you up and running "today", we took a hybrid approach:
- Vercel routes `/api/*` directly into the Express backend.
- The `DATA_ROOT`, originally hardcoded everywhere to the local folder, is gracefully bridged to the `/tmp` OS directory in the `api/index.js` function. This prevents `multer`, `node-persist`, and thumbnails from crashing the server on boot and upload.
- While `/tmp` resets between sessions (Vercel is serverless), we now have a **Storage Abstraction Seam** (`src/supabase.js`) hooked in.

## Next Step (After Deployment)
Once your Vercel URL resolves, you'll see the frontend try to talk to the backend. Your next priority is swapping existing routes inside `/src/endpoints/chats.js` and `characters.js` to call the new `uploadToStorage` methods we put in `src/supabase.js` instead of `fs.writeFileSync`.
